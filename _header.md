# OpenTelekomCloud Compute Instance Terraform Module

[![Changelog](https://img.shields.io/badge/changelog-release-green.svg)](CHANGELOG.md) [![Apache V2 License](https://img.shields.io/badge/license-Apache%20V2-orange.svg)](LICENSE)

This module creates an OTC compute instance with optional key-pair management,
boot disks, data volumes and volume attachments.

# Features

- **Instance Configuration**: Image or volume boot, flavors, networking, metadata and tags.
- **Image Selection**: Pinned image UUID, image name or filtered image lookup.
- **SSH Access**: Existing key-pair selection or optional key-pair creation.
- **Storage**: Boot block devices and attached EVS v3 or Block Storage v2 data volumes.
- **Guest Bootstrap**: Optional user data and configuration drive.
- **Operations**: Power state, recovery, scheduling hints and operation timeouts.

# Setup Requirements

Supply OTC credentials through supported provider environment variables, such as
`OS_AUTH_URL`, `OS_USERNAME`, `OS_PASSWORD`, `OS_DOMAIN_NAME`, `OS_PROJECT_NAME`
and `OS_REGION`. Both example providers use that environment configuration;
no authentication endpoint or region is hard-coded.
Both examples have no required input variables. Each creates its own VPC and
subnet and selects a public Ubuntu image by name. The full example selects the
first available compute zone from the configured region and uses it for both
the instance and its data volume. The sample image, flavor and SSD storage must
be available there; adjust the sample values if needed.
For reproducible deployments, replace the moving image lookup with a pinned image ID.

The default example demonstrates basic instance creation without a public IP or
SSH key pair. Use the full example when demonstrating SSH key configuration and
additional storage. Its example key pair is generated by the provider; no existing
key pair or personal public key is required.
